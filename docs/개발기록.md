# 카톡 릴레이 (문자 → PC 카카오톡)

앱을 설치할 수 없는 발신 휴대폰에서 **문자만** 보내면, PC의 카카오톡이 대신 메시지를 전송합니다.

```
[보내는 폰] ──문자──> [수신용 공기계] ──HTTP──> [PC: Relay.ps1] ──Win32──> [PC 카카오톡]
```

의존성이 없습니다. PowerShell 5.1 내장 기능만 사용하므로 **아무것도 설치할 필요가 없습니다.**

---

## 동작 원리 (실측 기반)

카톡 PC판을 포커스를 빼앗지 않고 백그라운드로 조작합니다. 실측으로 알아낸 내용은 다음과 같습니다:

| 항목 | 결과 |
|---|---|
| 채팅방 창 클래스 | **메인창과 똑같은 `EVA_Window_Dblclk` 입니다.** 클래스로는 구분하지 못합니다. 메인창은 `ChatRoomListCtrl` 자식 유무로, 채팅방 창은 `RICHEDIT50W` 유무로 판별합니다 |
| 검색창 주입 | 메인창의 0크기 `Edit` 에 `WM_SETTEXT` 를 보내면 백그라운드에서도 검색이 동작합니다 |
| 검색창 Enter | 채팅방이 열리지 않습니다. 결과 행에 `WM_LBUTTONDBLCLK` 를 보내야 합니다 |
| 입력창 `WM_SETTEXT` | 글자는 들어갑니다. 다만 **카톡이 인지하지 못해 전송 버튼이 회색 그대로여서** 전송하지 못합니다 |
| 입력창 `EM_REPLACESEL` | 실제 편집으로 처리되어 **전송 버튼이 활성화됩니다.** 이 방식을 사용합니다 |
| Enter 로 전송 | 입력창에 실제 포커스가 있어야만 동작합니다. 포커스가 없으면 줄바꿈만 들어갑니다 |
| 전송 버튼 클릭 | 포커스가 없어도 전송합니다. 버튼은 별도 HWND 가 아니라 창에 그려져 있습니다. 그래서 **창 우하단 기준 오프셋**(기본 `58,29`)으로 좌표를 계산합니다 |
| `PrintWindow` 캡처 | EVA 커스텀 렌더링이라 백지만 나옵니다. 화면 캡처(`CopyFromScreen`)를 사용합니다 |
| 빈 입력창 읽기 | `WM_GETTEXT` 가 플레이스홀더 `메시지 입력` 을 돌려줍니다. 그래서 단순 공백 검사로는 전송 성공을 판정하지 못합니다 |
| 카톡이 트레이에 있을 때 | 메인창은 살아 있지만 `Visible=False` 입니다. 검색어는 주입되지만 **결과 더블클릭이 동작하지 않습니다.** `SW_SHOWNOACTIVATE` 로 잠깐 표시해야 합니다 |
| 트레이 복원 시점 | 전송 도중에 메인창을 `SW_HIDE` 하면 **카톡이 채팅방 창까지 함께 정리**합니다. 전송이 모두 끝난 뒤에 숨겨야 합니다 |
| 채팅방을 열 때 포커스 | 카톡이 새 채팅방 창을 활성화해 포커스를 가져갑니다. 전송 전에 전경 창을 기억했다가 `AttachThreadInput` + `SetForegroundWindow` 로 되돌립니다 |

전송 절차는 다음과 같습니다:

```
방 찾기 (없으면 검색 → 결과 더블클릭으로 열기)
  → EM_SETSEL 전체선택 → EM_REPLACESEL 로 본문 주입 (전송 버튼 활성화됨)
  → 우하단 전송 버튼에 클릭 메시지
  → 입력창에서 본문이 사라졌는지 확인 (전송 성공 판정)
  → 채팅방 창 닫기 (closeAfterSend, 기본 켜짐 / 전송 실패해도 닫는다)
```

전송 후에는 채팅방 창을 닫아 창이 쌓이지 않게 합니다. 전송에 실패해도 닫습니다
(실패 시에는 입력창을 비운 뒤 닫으므로 다음 전송에 이전 내용이 남지 않습니다).
`config.json` 의 `closeAfterSend` 를 `false` 로 두면 창을 열어 둔 채로 유지합니다.

> 안전장치: 채팅방이 새 창이 아니라 메인창 안에서 열린 경우(`inline`)에는
> 창 핸들이 메인창이므로 절대 닫지 않습니다. 닫으면 카톡이 종료됩니다.

## 문자 형식

구분자는 **맨 처음 띄어쓰기** 하나뿐입니다. 예전에는 `/` 도 구분자로 받았습니다.
하지만 `3/4일` 같은 날짜가 들어간 문자가 잘려서 규칙을 하나로 줄였습니다.

`requirePassword: false` (현재 설정):

```
채팅방이름 보낼내용
```

예: `엄마 오늘 좀 늦어요`

`requirePassword: true` 로 두면 맨 앞에 비밀번호가 붙습니다:

```
비밀번호 채팅방이름 보낼내용
```

대상 지정:

```
@채팅방          그 뒤로는 이름 없이 내용만 보내도 그 방으로 간다
@채팅방 내용     지정하면서 그 문자를 바로 보낸다
@               지정을 푼다
```

공통:
- 채팅방 이름 대신 `aliases` 에 등록한 **별칭**을 써도 됩니다
- `defaultRoom` 을 설정하면 채팅방 이름도 생략할 수 있습니다
- 첫 띄어쓰기 뒤는 무엇이든 그대로 전달합니다. `/` 든 줄바꿈이든 손대지 않습니다
- 대상을 지정해 둔 동안에는 본문 전체가 내용입니다

> **비밀번호를 끄면 보호 수단이 하나만 남습니다.**
> 남는 것은 `allowFrom`(발신번호 화이트리스트)뿐입니다.
> 발신번호를 위조한 문자는 막지 못합니다. 같은 네트워크에서 릴레이로 직접 보낸 요청도 막지 못합니다.
> 집 와이파이에서 개인용으로 쓰는 정도면 감수할 만합니다.
> 다만 포워딩 앱에서 발신자 필터를 `모든 번호` 로 두었다면 반드시 켜야 합니다.

## 채팅방 여는 방식 두 가지

### 자동 열기 (`autoOpen: true`, 기본값)
채팅방이 열려 있지 않으면 릴레이가 직접 엽니다.
검색창에 채팅방 이름을 주입하고, 검색 결과 첫 행을 더블클릭한 뒤, 열린 창으로 전송합니다.

카톡 검색창이 백그라운드 Win32 메시지(`WM_SETTEXT`)에 반응하는 것은 실측으로 확인했습니다.
남은 변수는 **검색 결과 첫 행의 y좌표** 하나뿐입니다. 이 값은 한 번만 보정합니다:

```powershell
.\Calibrate-Open.ps1 -Room "지금 닫혀 있는 아무 채팅방 이름"
```

실측한 오프셋은 `config.json`의 `rowOffsets` 맨 앞에 저장합니다.
보정 스크립트는 **메시지를 보내지 않고 채팅방만 열어 봅니다.**
엉뚱한 채팅방이 열리면 제목을 비교해 바로 닫고 다음 후보 좌표로 넘어갑니다.

한계: 카톡 검색은 채팅방 이름뿐 아니라 **대화 내용도 검색**합니다.
채팅방 이름이 너무 짧거나 흔하면 엉뚱한 결과가 먼저 뜰 수 있습니다.
`aliases`로 짧은 별칭을 정확한 전체 채팅방 이름에 매핑해 두면 좋습니다.

### 미리 열어두기 (`autoOpen: false`, 가장 안정적)
쓸 채팅방을 새 창으로 띄워 두면 릴레이는 창 제목만으로 찾습니다.
좌표에 의존하지 않아 카톡을 업데이트해도 그대로 동작합니다.

1. 카톡 설정 > 채팅 > `채팅방을 새 창으로 열기` 켜기
2. 쓸 채팅방 더블클릭해서 창 띄우기 (최소화해도 됨)
3. `.\Show-Rooms.ps1` 로 확인

두 방식은 함께 동작합니다. 창이 이미 열려 있으면 그 창을 쓰고, 없을 때만 자동으로 엽니다.

> 카톡 화면잠금이 걸려 있으면 어느 방식도 동작하지 않습니다.

## 설치 / 실행

```powershell
cd C:\경로\kakao-relay

# 1) 열려 있는 채팅방 확인
.\Show-Rooms.ps1

# 2) 자동 열기 보정 (한 번만) - 메시지 안 보냄
.\Calibrate-Open.ps1 -Room "채팅방이름"

# 3) 수동 전송 테스트 (드라이런 - 실제로 안 보냄)
.\Send-Test.ps1 -Room "채팅방이름" -Text "테스트" -AutoOpen

# 4) 진짜 보내보기 (전송 후 창은 자동으로 닫힌다. 유지하려면 -KeepOpen)
.\Send-Test.ps1 -Room "채팅방이름" -Text "테스트" -AutoOpen -Live

# 5) config.json 수정: password / allowFrom / aliases / dryRun:false

# 6) 서버 실행
.\Relay.ps1

# 7) 로그온 시 자동 실행 등록
.\Install-Autostart.ps1

# 8) 방화벽은 Setup.ps1 이 함께 처리한다 (관리자 권한 필요)
```

## config.json

| 키 | 설명 |
|---|---|
| `port` | 릴레이 수신 포트 (기본 8787) |
| `requirePassword` | `false` 면 문자 앞 비밀번호를 생략합니다 |
| `password` | `requirePassword: true` 일 때 문자 맨 앞에 붙일 비밀번호 |
| `allowFrom` | 허용 발신번호 배열입니다. 하이픈과 `+82` 는 무시하고 매칭합니다. 빈 배열이면 모든 번호를 허용하므로 위험합니다 |
| `aliases` | `"짧은이름": "실제 채팅방 이름"` 매핑 |
| `defaultRoom` | 채팅방 이름을 생략했을 때 쓰는 기본 채팅방입니다. `null`이면 이름을 항상 적어야 합니다 |
| `sendMode` | `replacesel`(기본), `clipboard`(클립보드를 덮어쓰는 방식), `settext` |
| `smsReply` | 기본값은 `true` 입니다. 답장 문자를 보낼지 정합니다 |
| `dedupeSeconds` | **전송에 성공한** 메시지를 이 시간 동안 기억해 중복 전송을 막습니다 (기본 300초) |
| `retryCount` / `retryDelayMs` | 전송 실패 시 릴레이 자체 재시도 횟수/간격 (기본 2회 / 1500ms) |
| `closeAfterSend` | `true`(기본)면 전송 후 채팅방 창을 닫습니다 (성공/실패 무관) |
| `dryRun` | `true`면 창만 찾고 실제로 전송하지 않습니다. **처음에는 true 로 검증합니다** |

## HTTP 엔드포인트

| 경로 | 설명 |
|---|---|
| `GET /health` | 생존 확인 |
| `GET /rooms` | 현재 열려 있는 채팅방 창 목록 |
| `POST /sms` | 문자를 받습니다. JSON, form-urlencoded, 쿼리스트링, **text/plain 평문** 을 모두 허용합니다 |
| | `Content-Type: text/plain` 또는 `?raw=1` 이면 본문 전체를 메시지로 취급합니다 (이스케이프가 필요 없습니다) |

발신번호 필드는 `from`, `sender`, `phone`, `number`, `msisdn` 중 아무거나 인식합니다.
본문 필드는 `text`, `content`, `msg`, `message`, `body`, `sms` 중 아무거나 인식합니다.
(문자 포워더 앱마다 필드명이 달라서 모두 받아들이도록 했습니다)

```bash
curl -X POST http://<PC_IP>:8787/sms \
  -H 'Content-Type: application/json' \
  -d '{"from":"01012345678","text":"mypw1234 홍길동 테스트"}'
```

## 문자 수신 방법

### A안: 중계 휴대폰 + 알뜰폰 유심 (채택)

`Setup.ps1` 을 실행하면 이 PC 의 LAN IP 와 중계 휴대폰에 넣을 웹훅 주소를 출력합니다.
형태는 다음과 같습니다 (`<PC_IP>` 자리에 실제 주소가 들어갑니다):

```
http://<PC_IP>:8787/sms
```

> DHCP라 공유기가 IP를 바꿀 수 있습니다. 공유기 설정에서 이 PC 를 **DHCP 고정 할당**해 두면 좋습니다.
> (공유기 관리 페이지는 보통 게이트웨이 주소입니다. `ipconfig` 로 확인합니다)

**중계 휴대폰 세팅 — MacroDroid (권장)**

`SMS to URL Forwarder` 같은 전용 포워딩 앱은 Play Protect 가 스파이웨어로 분류해
설치를 막는 경우가 있습니다. 문자를 읽어 외부로 보내는 동작이 스파이웨어와 구분되지 않기 때문입니다.
MacroDroid 는 범용 자동화 앱이라 이 문제가 없습니다.

1. 데이터 0GB 최저 요금제 유심 꽂기 (문자 수신은 무료)
2. 플레이스토어에서 **MacroDroid** 설치 (무료 버전은 매크로 5개까지 만들 수 있고, 여기서는 1개만 씁니다)
3. 매크로 새로 만들기:
   - **트리거**: `SMS 수신` (SMS Received)
     - 발신자를 발신 휴대폰 번호로 지정하거나, `모든 번호` 로 두고 릴레이의 `allowFrom` 으로 거릅니다
   - **액션**: `HTTP 요청` (HTTP Request)
     - Method: `POST`
     - URL: `http://<PC_IP>:8787/sms?from={sms_number}`
     - Content Type: `text/plain`
     - Body: `{sms_message}`
4. SMS 읽기 권한 허용
5. 설정 > 배터리 > MacroDroid **절전 최적화 해제** (해제하지 않으면 며칠 뒤 동작이 멈춥니다)
6. PC 와 **같은 와이파이**에 연결하고, 충전기를 꽂아 상시 켜 두기

`{sms_number}` `{sms_message}` 는 MacroDroid 의 magic text 입니다.

> **평문(text/plain) 모드를 써야 본문이 깨지지 않습니다.**
> JSON 템플릿에 문자 내용을 그대로 끼워 넣으면 본문에 `"` 나 `\` 가 들어갔을 때 JSON 이 깨집니다.
> 폼 형식은 `&` 와 `=` 에서 깨집니다. MacroDroid 는 값을 이스케이프하지 않습니다.
> `text/plain` 은 본문 전체를 메시지로 그대로 받으므로 어떤 문자가 와도 안전합니다.
> 실측 확인: `"` `&` `=` `%` `\` 를 모두 정상 전달했습니다.

**대안: SMS to URL Forwarder (F-Droid)**
Play Protect 검사를 꺼야 설치되는 경우가 많습니다. 쓰려면 다음과 같이 설정합니다:
- 앱: `tech.bogomolov.incomingsmsgateway`
  (https://f-droid.org/en/packages/tech.bogomolov.incomingsmsgateway/)
- URL 을 `http://<PC_IP>:8787/sms?raw=1` 로 두고
  Content type 을 `text/plain`, 템플릿을 `%text%` 로 하면 똑같이 안전합니다.
  (기본 JSON 템플릿은 `{"from":"%from%","text":"%text%"}`)

**연결 확인**
```powershell
# PC에서 릴레이 실행 후, 공기계 브라우저에서 접속:
#   http://<PC_IP>:8787/health
# {"ok":true,...} 가 뜨면 성공
```

### B안: USB GSM 모뎀
`Modem-Ingest.ps1` 을 참고합니다. **하드웨어가 없어 아직 검증하지 못했습니다.** 실물 동글을 연결한 뒤 다듬어야 합니다.

## 보안

- `password`는 반드시 변경합니다. 문자는 발신번호를 위조할 수 있어 발신번호만으로는 부족합니다
- `allowFrom`은 비워 두지 않습니다
- 릴레이 포트는 사설망(집 와이파이)에만 엽니다. 포트포워딩으로 외부에 노출하지 않습니다
- 릴레이가 모든 수신·전송 시도를 `relay.log`에 기록합니다

## 주의

카카오톡 자동화는 이용약관상 회색지대입니다. 개인 용도로만, 낮은 빈도로 사용합니다.
대량 발송에 쓰면 계정 제재 대상이 될 수 있습니다.

실제로 돌려서 확인한 것:

- 비밀번호 불일치 / 형식 오류 / 중복 문자 — 정상 거부
- 전송 후 창 닫기 — 성공/실패 모두 닫힘 확인, `-KeepOpen` 시 유지 확인
- **카톡이 트레이에 내려가 있는 상태에서 전송** — 성공 (약 5초).
  메인창을 잠깐 표시 → 자동열기 → 전송 → 채팅방 닫기 → 메인창 재숨김 → 포커스 원복까지 확인
- **창 위치/크기 변경 내성** — 8가지 배치에서 전부 성공:
  380x450(최소) / 380x1000(세로) / 1200x560(가로) / 1500x1000(전체화면급) /

- JSON / form-urlencoded / 쿼리스트링 파싱 — 전부 정상

아직 검증하지 못한 것:

- **중계 휴대폰에서 PC 로 실제 문자 포워딩** (중계 휴대폰 세팅 후 확인 필요)

## 다른 PC 로 옮기기 / 남에게 넘기기

### 배포본 만들기

```powershell
.\Export-Package.ps1            # dist\kakao-relay-setup 폴더와 zip 을 함께 만듭니다
```

개인정보가 담긴 파일은 자동으로 제외합니다:

| 제외 | 이유 |
|---|---|
| `config.json` | 전화번호, 허용 IP, 채팅방 별칭 |
| `relay.log` / `watchdog.log` | 주고받은 메시지 내용이 남아 있습니다 |
| `fail-shot.png` | 실패 당시 채팅 화면 캡처 |

### 새 PC 에서 설치

```powershell
# 1) 폴더 복사 후, 관리자 PowerShell 에서
.\Setup.ps1
```

`Setup.ps1` 이 하는 일:

1. 카카오톡 설치 여부와 실행 여부를 확인합니다
2. **LAN IP 를 자동으로 감지해** 허용 IP 대역(`192.168.x.*`)을 그 값으로 설정합니다
3. 전화번호를 물어본 뒤 `config.sample.json` 을 바탕으로 `config.json` 을 생성합니다
   (이미 `config.json` 이 있으면 건드리지 않습니다)
4. 방화벽 규칙을 추가합니다 (관리자 권한이면 자동으로 추가하고, 아니면 명령어를 알려줍니다)
5. 작업 스케줄러에 릴레이와 감시자를 등록한 뒤 시작합니다
6. **중계 휴대폰에 넣을 웹훅 URL 을 출력합니다**

### 새 PC 에서 사람이 해야 하는 것

| 할 일 | 비고 |
|---|---|
| 카카오톡 설치 + 로그인 | 자동 로그인 켜두기, **화면잠금은 끄기** |
| `config.json` 의 `aliases` 채우기 | 채팅방 이름은 계정마다 다릅니다 |
| 중계 휴대폰의 문자 포워더에 새 URL 입력 | PC 가 바뀌면 IP 도 바뀝니다 |
| 공유기에서 PC 와 중계 휴대폰의 IP 고정 할당 | 권장 |
| 절전 모드 끄기 | 절전 모드에 들어가면 동작하지 않습니다 |
| `dryRun` 을 `false` 로 | 테스트가 끝난 뒤에 |

### PC 마다 달라서 다시 맞춰야 할 값

| 값 | 설명 |
|---|---|
| `allowIPs` | LAN 대역이 다르면 새로 설정합니다 (`Setup.ps1` 이 자동으로 처리합니다) |
| `allowFrom` | 발신 휴대폰 번호입니다 |
| `aliases` | 카톡 계정이 다르면 채팅방 이름도 다릅니다 |
| `rowOffsets` | 검색 결과 행 좌표입니다. 맞지 않으면 `Calibrate-Open.ps1` 로 다시 보정합니다 |
| `sendButton` | 전송 버튼 오프셋입니다. 보통은 픽셀 탐지가 자동으로 찾으므로 손댈 일이 없습니다 |

> 디스플레이 배율이 100% 가 아닌 PC 는 검증하지 않았습니다.
> 전송하지 못하면 `fail-shot.png` 와 `relay.log` 를 먼저 확인합니다.

## 아직 처리하지 못한 것

- 장문(MMS)은 전달하지 않습니다. `SMS 수신` 트리거가 MMS 를 감지하지 못합니다.
  알림 트리거를 쓰면 받을 수 있습니다. 다만 지난 알림이 다시 올라와 재전송되는 문제가 있어 권하지 않습니다.
- PC 가 꺼져 있거나 절전 상태면 동작하지 않습니다.
- 카톡이 로그아웃되거나 화면잠금이 걸려 있으면 전송하지 못합니다 (기록에는 남습니다).
- 디스플레이 배율 100% 에서만 검증했습니다.
