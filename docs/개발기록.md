# 카톡 릴레이 (문자 → PC 카카오톡)

앱을 설치할 수 없는 폰에서 **문자만** 보내면, PC의 카카오톡이 대신 메시지를 전송한다.

```
[보내는 폰] ──문자──> [수신용 공기계] ──HTTP──> [PC: Relay.ps1] ──Win32──> [PC 카카오톡]
```

의존성 없음. PowerShell 5.1 내장 기능만 사용하므로 **아무것도 설치할 필요 없다.**

---

## 동작 원리 (실측 기반)

카톡 PC판을 포커스를 뺏지 않고 백그라운드로 조작한다. 삽질해서 알아낸 것들:

| 항목 | 결과 |
|---|---|
| 채팅방 창 클래스 | **메인창과 똑같은 `EVA_Window_Dblclk`.** 클래스로는 구분 불가 — 메인창은 `ChatRoomListCtrl` 자식 유무로, 채팅방 창은 `RICHEDIT50W` 유무로 판별 |
| 검색창 주입 | 메인창의 0크기 `Edit` 에 `WM_SETTEXT` → 백그라운드에서도 검색 동작 |
| 검색창 Enter | 방이 안 열림. 결과 행에 `WM_LBUTTONDBLCLK` 를 보내야 함 |
| 입력창 `WM_SETTEXT` | 글자는 들어가지만 **카톡이 인지 못 해 전송 버튼이 회색 그대로** → 전송 불가 |
| 입력창 `EM_REPLACESEL` | 실제 편집으로 처리되어 **전송 버튼이 활성화됨** ← 이걸 써야 함 |
| Enter 로 전송 | 입력창에 실제 포커스가 있어야만 동작. 없으면 그냥 줄바꿈이 들어감 |
| 전송 버튼 클릭 | 포커스 없이도 전송됨. 버튼은 별도 HWND 가 아니라 창에 그려져 있어서 **창 우하단 기준 오프셋**(기본 `21,29`)으로 좌표 계산 |
| `PrintWindow` 캡처 | EVA 커스텀 렌더링이라 백지만 나옴. 화면 캡처(`CopyFromScreen`)를 써야 함 |
| 빈 입력창 읽기 | `WM_GETTEXT` 가 플레이스홀더 `메시지 입력` 을 돌려줌 → 단순 공백검사로 전송 성공을 판정하면 안 됨 |
| 카톡이 트레이에 있을 때 | 메인창이 살아있지만 `Visible=False`. 검색어 주입은 되지만 **결과 더블클릭이 안 먹는다** → `SW_SHOWNOACTIVATE` 로 잠깐 표시해야 함 |
| 트레이 복원 시점 | 전송 도중에 메인창을 `SW_HIDE` 하면 **카톡이 채팅방 창까지 같이 정리**해버린다 → 전송이 전부 끝난 뒤에 숨겨야 함 |
| 방을 열 때 포커스 | 카톡이 새 채팅방 창을 활성화해 포커스를 가져간다 → 전송 전 전경 창을 기억했다가 `AttachThreadInput` + `SetForegroundWindow` 로 되돌린다 |

따라서 전송 절차는:

```
방 찾기 (없으면 검색 → 결과 더블클릭으로 열기)
  → EM_SETSEL 전체선택 → EM_REPLACESEL 로 본문 주입 (전송 버튼 활성화됨)
  → 우하단 전송 버튼에 클릭 메시지
  → 입력창에서 본문이 사라졌는지 확인 (전송 성공 판정)
  → 채팅방 창 닫기 (closeAfterSend, 기본 켜짐 / 전송 실패해도 닫는다)
```

전송 후에는 채팅방 창을 닫아 창이 쌓이지 않게 한다. 전송에 실패해도 닫는다
(실패 시에는 입력창을 비운 뒤 닫으므로 다음 전송에 찌꺼기가 남지 않는다).
`config.json` 의 `closeAfterSend` 를 `false` 로 두면 열어둔 채로 유지한다.

> 안전장치: 채팅방이 새 창이 아니라 메인창 안에서 열린 경우(`inline`)에는
> 대상 핸들이 메인창이므로 절대 닫지 않는다. 닫으면 카톡 자체가 종료된다.

## 문자 형식

`requirePassword: false` (현재 설정):

```
채팅방이름/보낼내용
```

예: `나/오늘 좀 늦어요`

`requirePassword: true` 로 두면 맨 앞에 비밀번호가 붙는다:

```
비밀번호/채팅방이름/보낼내용
```

공통:
- 채팅방 이름 대신 `aliases` 에 등록한 **별칭**을 써도 된다
- `defaultRoom` 을 설정하면 채팅방 이름도 생략할 수 있다
- 내용에 `/` 가 들어가도 괜찮다 (앞에서만 잘라낸다)

> **비밀번호를 끄면 무엇을 포기하는가**
> 보호막이 `allowFrom`(발신번호 화이트리스트) 하나만 남는다.
> 즉 발신번호를 위조한 문자, 또는 같은 네트워크에서 릴레이로 직접 보낸 요청을 막지 못한다.
> 집 와이파이에서 개인용으로 쓰는 정도면 감수할 만하지만,
> 포워딩 앱에서 발신자 필터를 `모든 번호` 로 두는 경우에는 반드시 켜야 한다.

## 채팅방 여는 방식 두 가지

### 자동 열기 (`autoOpen: true`, 기본값)
방이 안 열려 있으면 릴레이가 알아서 연다.
검색창에 방 이름을 주입 → 검색 결과 첫 행을 더블클릭 → 열린 창에 전송.

카톡 검색창이 백그라운드 Win32 메시지(`WM_SETTEXT`)에 반응하는 것은 실측으로 확인됐다.
남은 변수는 **검색 결과 첫 행의 y좌표** 하나뿐이고, 이건 한 번만 보정하면 된다:

```powershell
.\Calibrate-Open.ps1 -Room "지금 닫혀 있는 아무 채팅방 이름"
```

실측한 오프셋이 `config.json`의 `rowOffsets` 맨 앞에 저장된다.
보정 스크립트는 **메시지를 보내지 않고 방만 열어본다.**
엉뚱한 방이 열리면 제목을 비교해서 즉시 닫고 다음 후보 좌표로 넘어간다.

한계: 카톡 검색은 채팅방 이름뿐 아니라 **대화 내용도 검색**한다.
방 이름이 너무 짧거나 흔하면 엉뚱한 결과가 먼저 뜰 수 있으므로,
`aliases`로 짧은 별칭 → 정확한 전체 방 이름으로 매핑해 두는 것이 좋다.

### 미리 열어두기 (`autoOpen: false`, 가장 안정적)
쓸 채팅방을 새 창으로 띄워 놓으면 릴레이는 창 제목으로 찾기만 하면 된다.
좌표에 의존하지 않아 카톡 업데이트에도 안 깨진다.

1. 카톡 설정 → 채팅 → `채팅방을 새 창으로 열기` 켜기
2. 쓸 채팅방 더블클릭해서 창 띄우기 (최소화해도 됨)
3. `.\Show-Rooms.ps1` 로 확인

두 방식은 함께 동작한다. 창이 이미 열려 있으면 그걸 쓰고, 없을 때만 자동으로 연다.

> 카톡 화면잠금이 걸려 있으면 어느 방식도 동작하지 않는다.

## 설치 / 실행

```powershell
cd C:\Users\Chan\kakao-relay

# 1) 열려 있는 채팅방 확인
.\Show-Rooms.ps1

# 2) 자동 열기 보정 (한 번만) - 메시지 안 보냄
.\Calibrate-Open.ps1 -Room "채팅방이름"

# 3) 수동 전송 테스트 (드라이런 - 실제로 안 보냄)
.\Send-Test.ps1 -Room "채팅방이름" -Text "테스트" -AutoOpen

# 4) 진짜 보내보기 (전송 후 창은 자동으로 닫힌다. 유지하려면 -KeepOpen)
.\Send-Test.ps1 -Room "채팅방이름" -Text "테스트" -AutoOpen -Live

# 5) config.json 수정: password / allowFrom / aliases / dryRun:false

# 6) 서버 실행
.\Relay.ps1

# 7) 로그온 시 자동 실행 등록
.\Install-Autostart.ps1

# 8) 폰에서 접속하려면 방화벽 열기 (관리자 PowerShell에서 1회)
.\Allow-Firewall.ps1
```

## config.json

| 키 | 설명 |
|---|---|
| `port` | 릴레이 수신 포트 (기본 8787) |
| `requirePassword` | `false` 면 문자 앞 비밀번호를 생략한다 |
| `password` | `requirePassword: true` 일 때 문자 맨 앞에 붙일 비밀번호 |
| `allowFrom` | 허용 발신번호 배열. 하이픈/`+82` 무시하고 매칭. 빈 배열이면 전체 허용(위험) |
| `aliases` | `"짧은이름": "실제 채팅방 이름"` 매핑 |
| `defaultRoom` | 방 이름 생략 시 기본 채팅방. `null`이면 항상 필수 |
| `sendMode` | `settext`(기본) 또는 `clipboard`(줄바꿈/이모지에 강하나 클립보드를 덮어씀) |
| `dedupeSeconds` | **전송 성공한** 메시지를 이 시간 동안 기억해 중복 전송 차단 (기본 300초) |
| `retryCount` / `retryDelayMs` | 전송 실패 시 릴레이 자체 재시도 횟수/간격 (기본 2회 / 1500ms) |
| `closeAfterSend` | `true`(기본)면 전송 후 채팅방 창을 닫는다 (성공/실패 무관) |
| `dryRun` | `true`면 창만 찾고 실제 전송 안 함. **처음엔 true로 검증** |

## HTTP 엔드포인트

| 경로 | 설명 |
|---|---|
| `GET /health` | 생존 확인 |
| `GET /rooms` | 현재 열려 있는 채팅방 창 목록 |
| `POST /sms` | 문자 수신. JSON / form-urlencoded / 쿼리스트링 / **text/plain 평문** 모두 허용 |
| | `Content-Type: text/plain` 또는 `?raw=1` 이면 본문 전체를 메시지로 취급 (이스케이프 불필요) |

발신번호 필드는 `from`, `sender`, `phone`, `number`, `msisdn` 중 아무거나,
본문 필드는 `text`, `content`, `msg`, `message`, `body`, `sms` 중 아무거나 인식한다.
(SMS 포워더 앱마다 필드명이 달라서 전부 흡수하도록 해둠)

```bash
curl -X POST http://<PC_IP>:8787/sms \
  -H 'Content-Type: application/json' \
  -d '{"from":"01012345678","text":"mypw1234/홍길동/테스트"}'
```

## 문자 수신 방법

### A안: 공기계 + 알뜰폰 유심 (채택)

`Setup.ps1` 을 실행하면 이 PC 의 LAN IP 와 폰에 넣을 웹훅 주소를 출력해 준다.
형태는 다음과 같다 (`<PC_IP>` 자리에 실제 주소가 들어간다):

```
http://<PC_IP>:8787/sms
```

> DHCP라 공유기가 IP를 바꿀 수 있다. 공유기 설정에서 이 PC를 **DHCP 고정 할당**해두는 게 좋다.
> (공유기 관리 페이지는 보통 게이트웨이 주소. `ipconfig` 로 확인)

**공기계 세팅 — MacroDroid (권장)**

`SMS to URL Forwarder` 같은 전용 포워딩 앱은 Play Protect 가 스파이웨어로 분류해
설치를 막는 경우가 있다. 문자를 읽어 외부로 보내는 동작 자체가 스파이웨어와 구분되지 않기 때문이다.
MacroDroid 는 범용 자동화 앱이라 이 문제가 없다.

1. 데이터 0GB 최저 요금제 유심 꽂기 (문자 수신은 무료)
2. 플레이스토어에서 **MacroDroid** 설치 (무료 버전은 매크로 5개까지, 1개만 쓰면 된다)
3. 매크로 새로 만들기:
   - **트리거**: `SMS 수신` (SMS Received)
     - 발신자를 보내는 폰 번호로 지정하거나 `모든 번호` 로 두고 릴레이의 `allowFrom` 으로 거른다
   - **액션**: `HTTP 요청` (HTTP Request)
     - Method: `POST`
     - URL: `http://<PC_IP>:8787/sms?from={sms_number}`
     - Content Type: `text/plain`
     - Body: `{sms_message}`
4. SMS 읽기 권한 허용
5. 설정 → 배터리 → MacroDroid **절전 최적화 해제** (안 하면 며칠 뒤 조용히 죽는다)
6. PC 와 **같은 와이파이**, 충전기 꽂아서 상시 켜둘 것

`{sms_number}` `{sms_message}` 는 MacroDroid 의 magic text 다.

> **평문(text/plain) 모드를 쓰는 이유**
> JSON 템플릿에 문자 내용을 그대로 끼워 넣으면 본문에 `"` 나 `\` 가 들어갔을 때 JSON 이 깨진다.
> 폼 형식은 `&` `=` 에서 깨진다. MacroDroid 는 값을 이스케이프해주지 않는다.
> `text/plain` 은 본문 전체를 메시지로 그대로 받으므로 어떤 문자가 와도 안전하다.
> 실측 확인: `"` `&` `=` `%` `\` 전부 정상 전달.

**대안: SMS to URL Forwarder (F-Droid)**
Play Protect 검사를 꺼야 설치되는 경우가 많다. 쓰려면:
- 앱: `tech.bogomolov.incomingsmsgateway`
  (https://f-droid.org/en/packages/tech.bogomolov.incomingsmsgateway/)
- URL 을 `http://<PC_IP>:8787/sms?raw=1` 로 두고
  Content type 을 `text/plain`, 템플릿을 `%text%` 로 하면 동일하게 안전하다.
  (기본 JSON 템플릿은 `{"from":"%from%","text":"%text%"}`)

**연결 확인**
```powershell
# PC에서 릴레이 실행 후, 공기계 브라우저에서 접속:
#   http://<PC_IP>:8787/health
# {"ok":true,...} 가 뜨면 성공
```

## 보안

- `password`는 반드시 변경. 문자 스푸핑이 가능하므로 발신번호만으로는 부족하다
- `allowFrom`을 비워두지 말 것
- 릴레이 포트는 사설망(집 와이파이)에만 열 것. 포트포워딩으로 외부 노출 금지
- 모든 수신/전송 시도는 `relay.log`에 기록된다

## 주의

카카오톡 자동화는 이용약관상 회색지대다. 개인 용도로만, 낮은 빈도로 사용할 것.
대량 발송에 쓰면 계정 제재 대상이 될 수 있다.

## 검증 현황 (2026-08-20)

실제로 돌려서 확인한 것:

- 채팅방 창이 열려 있을 때 전송 — 성공
- 창을 닫은 상태에서 검색 자동 열기 후 전송 — 성공 (행 오프셋 자동 폴백 동작 확인)
- 한글 / 이모지 / 특수문자 / 긴 문장 — 성공
- 릴레이 HTTP 경유 (별칭, 전체 방이름, 본문에 `/` 포함) — 전부 성공
- 비밀번호 불일치 / 형식 오류 / 중복 문자 — 정상 거부
- 전송 후 창 닫기 — 성공/실패 모두 닫힘 확인, `-KeepOpen` 시 유지 확인
- **카톡이 트레이에 내려가 있는 상태에서 전송** — 성공 (약 5초).
  메인창을 잠깐 표시 → 자동열기 → 전송 → 채팅방 닫기 → 메인창 재숨김 → 포커스 원복까지 확인
- **창 위치/크기 변경 내성** — 8가지 배치에서 전부 성공:
  380x450(최소) / 380x1000(세로) / 1200x560(가로) / 1500x1000(전체화면급) /
  640x900 / 400x500 / 800x600 / 두 번째 모니터(2100,100)
  좌표를 전부 창 기준 상대값으로 매 전송마다 다시 계산하기 때문
- JSON / form-urlencoded / 쿼리스트링 파싱 — 전부 정상

아직 검증 안 된 것:

- **공기계 → PC 실제 문자 포워딩** (공기계 세팅 후 확인 필요)
- `Modem-Ingest.ps1` (B안, 하드웨어 없음)
- 카톡 UI 변경 시 전송 버튼 오프셋 재보정 필요 여부
- 디스플레이 배율(DPI) 변경 시 동작 (현재 100%에서만 확인)

## 다른 PC 로 옮기기 / 남에게 넘기기

### 배포본 만들기

```powershell
.\Export-Package.ps1            # 바탕화면에 kakao-relay-setup 폴더
.\Export-Package.ps1 -Zip       # zip 까지
```

개인정보가 담긴 파일은 자동으로 제외된다:

| 제외 | 이유 |
|---|---|
| `config.json` | 전화번호, 허용 IP, 채팅방 별칭 |
| `relay.log` / `watchdog.log` | 주고받은 메시지 내용이 남아 있음 |
| `fail-shot.png` | 실패 당시 채팅 화면 캡처 |

### 새 PC 에서 설치

```powershell
# 1) 폴더 복사 후, 관리자 PowerShell 에서
.\Setup.ps1
```

`Setup.ps1` 이 하는 일:

1. 카카오톡 설치/실행 여부 확인
2. **LAN IP 자동 감지** → 허용 IP 대역(`192.168.x.*`)을 그 값으로 설정
3. 전화번호를 물어보고 `config.sample.json` 을 바탕으로 `config.json` 생성
   (이미 `config.json` 이 있으면 건드리지 않는다)
4. 방화벽 규칙 추가 (관리자 권한이면 자동, 아니면 명령어를 알려준다)
5. 작업 스케줄러에 릴레이 + 감시자 등록 후 시작
6. **폰에 넣을 웹훅 URL 을 출력**

### 새 PC 에서 사람이 해야 하는 것

| 할 일 | 비고 |
|---|---|
| 카카오톡 설치 + 로그인 | 자동 로그인 켜두기, **화면잠금은 끄기** |
| `config.json` 의 `aliases` 채우기 | 채팅방 이름은 계정마다 다르다 |
| 폰 SMS 포워더에 새 URL 입력 | PC 가 바뀌면 IP 도 바뀐다 |
| 공유기에서 PC/폰 IP 고정 할당 | 권장 |
| 절전 모드 끄기 | 절전 들어가면 동작하지 않는다 |
| `dryRun` 을 `false` 로 | 테스트가 끝난 뒤에 |

### PC 마다 달라서 다시 맞춰야 할 값

| 값 | 설명 |
|---|---|
| `allowIPs` | LAN 대역이 다르면 새로 설정 (`Setup.ps1` 이 자동 처리) |
| `allowFrom` | 문자를 보낼 폰 번호 |
| `aliases` | 카톡 계정이 다르면 채팅방 이름도 다르다 |
| `rowOffsets` | 검색 결과 행 좌표. 안 맞으면 `Calibrate-Open.ps1` 로 재보정 |
| `sendButton` | 전송 버튼 오프셋. 보통은 픽셀 탐지가 알아서 찾으므로 손댈 일이 없다 |

> 화면 배율(DPI)이 100% 가 아닌 PC 는 검증하지 않았다.
> 전송이 안 되면 `fail-shot.png` 와 `relay.log` 를 먼저 확인할 것.

## 아직 처리 안 된 것

- **전송 결과를 회신하지 않는다.** 문자를 보낸 쪽에서는 성공했는지 알 수 없다.
  공기계가 문자 발신도 가능하면 회신 기능을 붙일 수 있다.
- PC가 꺼져 있거나 절전 상태면 당연히 동작하지 않는다.
- 카톡이 로그아웃되거나 화면잠금이 걸려 있으면 실패한다 (로그에는 남는다).
- 디스플레이 배율(DPI) 100% 에서만 검증했다.
